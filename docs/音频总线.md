# 音频总线（AudioBus / AudioVoice）

> 适用范围：Godot 4.7.2 / 本仓库
> 涉及文件：`scripts/audio/audio_bus.gd`、`scripts/audio/audio_voice.gd`、
> `default_bus_layout.tres`、`scripts/sfx.gd`
> 最近更新：2026-10-28

---

## 1. 为什么有这一层

在 AudioBus 之前，每个场景各自 `new AudioStreamPlayer`：门铃、服务铃、雨声、低频各建一份，
场景卸载时靠人记得 `stop()`。跨场景时雨声会重启成两层，剧情声道和场景环境声互相抢音量，
而且没有任何测试能发现「声音叠了」。

现在所有播放都经过 `AudioBus`（autoload），它只做四件事：

1. **合并**：2D 一次性音效并进每条总线一个复音播放器，不再一个音效一个节点；
2. **限流**：3D 一次性音效走固定 12 个播放器的池子，满了按优先级取舍；
3. **命名**：雨、低频、耳鸣这类长音用跨场景稳定的声道名管理，同名申请是接管；
4. **生命周期**：场景卸载时，它创建的播放器由它负责回收，不依赖调用方记得清理。

`AudioBus` 只持有自己创建的播放器。场景节点一律用 `instance_id + WeakRef` 引用，
不阻止场景卸载——autoload 活过场景切换，直接持有节点引用就是泄漏。

## 2. 总线布局

`default_bus_layout.tres`：

```
Master（挂 AudioEffectHardLimiter，ceiling −0.5 dB）
├── Ambience   雨、低频、耳鸣、剧情环境声
├── SFX        门铃、服务铃、脚步、撞击、广播
└── Music      目前空着，预留给 BGM
```

`AudioBus` 暴露常量 `BUS_AMBIENCE` / `BUS_SFX` / `BUS_MUSIC`，避免各处手写字符串。
`has_bus()` 可以判断总线是否存在；不存在的总线会 `push_warning` 并回落到 `SFX`。
砍掉或改名总线时，必须同步 `default_bus_layout.tres` 和所有调用点。

## 3. 四种播放形态

| 接口 | 形态 | 适合什么 | 返回 |
|---|---|---|---|
| `play_2d(stream, opts)` | 每条总线一个 `AudioStreamPlayer` + `AudioStreamPlaybackPolyphonic`，上限 16 条 | 门铃、服务铃、广播等一次性 2D 音效 | `AudioVoice` |
| `play_3d(stream, pos, opts)` | 固定 12 个 `AudioStreamPlayer3D` 的池子 | 世界里的短音效（撞击、擦身车） | **无**（池中的播放器随时会被抢走，拿句柄只会调错对象） |
| `play_on(emitter, stream, opts)` | 每个 3D 节点一个复音播放器，上限 8 条 | 连续触发、且需要跟着节点走的声音（自动门铃） | `AudioVoice` |
| `channel(id, stream, opts)` | 每个声道名一个专用播放器，可循环、淡变、2D/3D、跟随 | 雨、低频、耳鸣、剧情声道、循环广播 | `AudioVoice` |

### 3.1 一次性音效的优先级

`opts.priority` 默认 0。池子 / 复音槽满时：

- **严格更高优先级**才能抢走最低优先级的旧声音；
- 同优先级直接丢新声音——抢一个同样重要的声音来播另一个，听感上只是无故断一下。

3D 池被抢后，被抢的播放器会收到 `finished` 信号；实现里会检查 `playing`，
避免把刚被重新装填的播放器误删。

### 3.2 2D 复音的时序

`play_stream()` 之后音频线程要过一下才把流标成 `playing`。因此：

- 刚建好的流有 250ms 宽限期，不会被当成「已结束」清掉；
- 复音满了、已经 `stop_stream()` 一条，但槽位这一帧还没真正释放时，返回 `null`
  并把请求排到下一帧补播（`POLY_RETRY`）；
- **`play_2d()` 返回 `null` 不一定是失败**，可能只是晚一帧。probe 里就专门测了这一点。

### 3.3 3D 发射器

`play_on(emitter, ...)` 第一次调用时在 `emitter` 下建一个 `AudioStreamPlayer3D`，
之后同一发射器的多条流合并进它的复音 playback。`opts.offset` 是相对发射器的局部坐标，
只在第一次创建时应用。

自动门就是典型用法：音源挂在门体上，门节点被卸载时发射器跟着走，不会留在 `AudioBus` 里。
`play_on()` 要求发射器已经在场景树里，否则拒绝并警告。

## 4. 命名声道

这是跨场景唯一需要「记住名字」的接口。

### 4.1 申请与接管

```gdscript
_rain = AudioBus.channel(&"rain", load("res://audio/street_rain_loop.wav"), {
    "bus": AudioBus.BUS_AMBIENCE,
    "db": -12.5,          # 素材是 -23 LUFS 母版，这一档换算后有效 -35.5 LUFS
    "owner": self,
})
```

同一个 `id` 再次申请时：

| 情况 | 行为 |
|---|---|
| 同流、同 2D/3D、同 loop 设置，正在播放 | 更新音量 / 音高 / 总线 / 归属，不重启 |
| 同流，正在淡出 | 取消淡出，用 `TAKEOVER_FADE`（0.2s）淡回目标音量 |
| 流或 2D/3D 形态变了 | 销毁旧播放器，重建 |

这就是「商店街 → 加油站」不会叠出两层雨的原因。三个可玩场景都申请 `&"rain"` /
`&"hum"`，后到的场景接管还在淡出的旧声道。

**但「接管」不等于「无缝续播」。** `channel()` 判断是否同一个流，比的是 `source`；
换了流就落到上表第三行——销毁重建。商店街（`street_rain_loop.wav`）和
加油站（`gas_station_rain_loop.wav`）各用一条自己的 120s 雨声（2026-10-27 重制为三层结构），
在这两个场景之间是换带而不是续播；室内 `store_walk` 仍是 8s 的 `rain_loop.wav`。所有换带都发生在
黑卡转场后面，实际听不出来。要改回三场景共用一条流，就把 `stream` 统一即可。

### 4.2 声道名是跨场景接口

| 名字 | 归属 | 说明 |
|---|---|---|
| `rain` | store_walk / hoshi_street / gas_station | 环境雨，共用一个声道名；街 / 站各一条 120s 雨声（规格见 [雨声环境音规格.md](雨声环境音规格.md)），室内是闷版 |
| `hum` | store_walk / hoshi_street / gas_station | 店内 / 站内低频 |
| `story.radio` | gas_station_story | 收音机广播，剧情一次性 |
| `cutscene.rain` / `cutscene.drone` | opening_flow 的 cutscene | 开场演出专用，和场景雨分开 |
| `probe_*` | audio_probe | 测试用，不与正式声道重名 |

**新增跨场景环境声时复用稳定名字；新增剧情 / 演出声道时加前缀**，避免误接管。
名字一旦发布就是接口，改名等于让旧场景的声道失去接管关系，会叠音。

### 4.3 `owner` 与回收

```gdscript
"owner": self
```

- `owner` 默认是 `get_tree().current_scene`；**长音一定要显式绑定场景根**。
- 场景根 `tree_exiting` 时，`AudioBus` 把它名下所有声道一起淡出（0.25s），不用场景自己 `stop()`。
  这条只兜底「不是转场的卸载」；正常转场在加载屏一开始就由
  `AudioBus.cut_for_transition()` 统一切声，见 §7。
- 一个 owner 只连一条 `tree_exiting`：Godot 判断「重复连接」时不比较 bind 参数，
  第二条声道再连同一个方法会静默不连、卸载时漏收。实现里按 `owner_id` 收拢其名下所有声道。
- 循环声道不会自己从表里消失。要主动停，用 `AudioBus.stop_channel(id, seconds)`；
  它会把声道标成 `releasing` 并在淡出后删除。直接 `voice.stop()` 只会停播放，
  循环声道仍留在表里（这是 `cutscene.gd` 用 `stop_channel` 而不是 `voice.stop` 的原因）。

### 4.4 循环与流缓存

`Sfx.*` 返回的是 `static` 缓存里的同一个 `AudioStreamWAV` 实例。
直接改它的 `loop_mode` 会把所有使用同一份流的地方一起改成循环。

`channel(..., {"loop": true})`（默认）会在内部 `duplicate()` 一份 WAV 再设循环，
不会污染 `Sfx` 缓存。**不要在外面手动给 `Sfx.*` 的返回值设 loop。**

## 5. `AudioVoice` 句柄

`AudioVoice` 是 `RefCounted`，不是节点：句柄本身不进场景树，扔掉它声音照播；
它也不负责保活播放器——播放器归 `AudioBus` 管。

| 成员 | 说明 |
|---|---|
| `volume_db` / `pitch_scale` | 读写当前流的音量 / 音高 |
| `playing` | 是否还在播放；`stop()` 之后立即为 false，不等音频线程 |
| `set_position(pos)` | 只对 3D 专用播放器有意义；复音流的位置由所属播放器决定 |
| `fade_to(db, seconds)` | 淡到目标音量；`seconds <= 0` 立即生效 |
| `stop(seconds)` | 淡出后停止；`seconds <= 0` 立即停止 |
| `cancel_fade()` | 取消淡入淡出并停在当前音量；接管场景时用 |

不要在场景切换后继续持有句柄：句柄指向的播放器可能已经被 `AudioBus` 回收。
需要跨场景延续的声音，用命名声道重新申请，而不是缓存句柄。

## 6. 场景接入示例

### 6.1 环境声（三场景通用）

```gdscript
func _setup_audio() -> void:
    _rain = AudioBus.channel(&"rain", load("res://audio/street_rain_loop.wav"), {
        "bus": AudioBus.BUS_AMBIENCE,
        "db": -12.5,        # 街与站各用自己那条；室内 store_walk 仍用 rain_loop.wav
        "owner": self,
    })
    _hum = AudioBus.channel(&"hum", load("res://audio/drone_loop.wav"), {
        "bus": AudioBus.BUS_AMBIENCE,
        "db": -38.0,
        "owner": self,
    })
```

进店时只调 `fade_channel`，不要再 `channel()` 一次：

```gdscript
AudioBus.fade_channel(&"rain", -26.0, 0.6)
AudioBus.fade_channel(&"hum", -24.0, 0.6)
```

### 6.2 一次性 2D 音效

```gdscript
AudioBus.play_2d(Sfx.bell(), {"bus": AudioBus.BUS_SFX, "db": -8.0})
```

### 6.3 挂在物体上的 3D 音效

```gdscript
AudioBus.play_on(self, Sfx.chime(), {
    "db": -6.0,
    "unit_size": 4.0,
    "max_distance": 16.0,
    "offset": Vector3(DOOR_CENTER.x, 2.2, -0.9),
})
```

### 6.4 世界坐标的一次性 3D 音效

```gdscript
AudioBus.play_3d(Sfx.impact(), hit_position, {"db": -3.0, "priority": 5})
```

### 6.5 剧情声道

```gdscript
_radio = AudioBus.channel(&"story.radio", Sfx.radio(), {
    "bus": AudioBus.BUS_AMBIENCE,
    "db": -12.0,
    "owner": self,
    "loop": false,
})
```

`loop` 默认 `true`；一次性广播要显式关掉，播完自动回收。

## 7. 场景切换时的清理

### 7.1 转场切声

`SceneRouter.goto()` 通过全部校验、真正进入转场时，会调用
`AudioBus.cut_for_transition()`：

- 命名声道按 `TRANSITION_CUT`（0.2s）淡出并回收——雨、低频这类连续声床硬停会有爆音；
- 2D 复音流、待播请求、3D 池立即清空；
- 3D 发射器的播放器停止并释放。

所以旧场景的声音不会拖进加载屏，也不会出现「旧场景的雨还在下、新场景的雨又起来」。
新场景的 `_setup_audio()` 跑在 `change_scene_to_file` 之后，听到的永远是目的地自己的声音。

切声只归路由层管，场景代码不要自己停环境声来模拟转场；要停某条声道用 `stop_channel()`。
`cut_for_transition()` 目前会把所有声道一起切掉——将来真加跨场景 BGM，要在这里给它留豁免。

### 7.2 每帧兜底

`AudioBus` 每帧检查 `get_tree().current_scene` 的 `instance_id`：

- 场景变了 → 清掉旧场景的 2D 复音流、待播请求、3D 池条目；
- **命名声道不在此列**——它们跟 `owner` 走，由 `tree_exiting` 淡出；
- 跟随目标（`follow`）消失时，声道主动淡出，不会永久占着一个空位置。

所以：

- 一次性音效不需要手动停，场景切换会自动收；
- 长音必须传 `owner`，否则它会跨场景继续播，只能靠 `stop_channel` 收；
- 如果确实需要跨场景延续（例如全局 BGM），**不要**用 `owner`，并在文档里写清楚它归谁管。

## 8. 常见坑

- **不要在业务代码里 `new AudioStreamPlayer`。** 会绕过总线合并、优先级和场景清理。
  唯一例外是 `AudioBus` 内部；新增播放形态时改 `AudioBus`，不要在场景里开小灶。
- **不要改 `Sfx.*` 返回的流。** 它们是 `static` 缓存；循环、音量、循环点都在 `AudioBus`
  内部对副本处理。
- **`play_3d()` 故意不返回句柄。** 池子里的播放器随时会被更高优先级的音效抢走。
  需要控制的 3D 声音用 `play_on()` 或 `channel()`。
- **循环声道不要用 `voice.stop()` 收尾。** 播放器停了但表项还在；用 `AudioBus.stop_channel()`。
- **同名声道是接管，不是叠加。** 如果听到两层雨，先查是不是有人用了不同的声道名。
- **`play_2d()` 返回 `null` 可能只是下一帧补播。** 不要把它当成「播放失败」立即重试，
  否则会塞两条。
- **优先级只在严格更高时抢占。** 同优先级的音效多了会丢新的，不会互相打断。
- **缺 `.godot` 导入时音频加载失败。** 场景看起来像「少了声音」，不是 AudioBus 的 bug。
  新机器先让 Godot 完成一次导入。

## 9. 验证

```bash
./tools/run.sh --headless audio_probe
./tools/check.sh
```

`audio_probe` 现在 49 条断言，覆盖：

- autoload 与三条总线存在、Master 限幅器已挂；
- 2D 合并、上限、同优先级丢弃、高优先级抢占后下一帧补播、播完回收；
- 3D 固定池上限与回收；
- 同一发射器只建一个播放器、发射器释放后回收；
- 命名声道循环、淡变、淡出中被接管、换流重建、`stop_channel(0)` 立即移除；
- 同一 owner 两条声道的生命周期；
- 非循环声道播完自动回收；
- 转场切声：声道 / 2D / 3D 池 / 发射器一起收，切完新场景能立刻重新申请；
- 总线音量设置与淡变。

探针里有真实等待时间的计时器，30 秒看门狗会兜底，避免脚本报错后挂死 `check.sh`。
**听感问题 probe 测不了**——音量平衡、音色是否刺耳仍需手动试听；probe 只保证
「合并、抢占、接管、回收」这些看日志看不出来的事。
