# 场景路由

> 适用范围：Godot 4.7.2 / 本仓库
> 涉及文件：`scripts/core/game_state.gd`、`scripts/core/world_links.gd`、
> `scripts/core/scene_router.gd`、`scripts/core/portal_host.gd`、`scripts/letter_transition.gd`
> 最近更新：2026-10-24

---

## 1. 它解决什么问题

路由层落地前，「从这里去那里」的判断分散在各个场景脚本里：

- 出口长什么样（触发盒 / 提示点）和出口通向哪写在一起；
- 「逢魔时之后不能回商店街」这类剧情条件要散落在两个场景里各写一遍；
- 想验证跨场景行为，只能真的加载两个场景；
- 从加油站回商店街时，如果反向出口也写 `set_story_node`，剧情会被倒回上一幕。

现在的拆分原则只有一句：**出口本地化，目的地集中化。**

| 层 | 知道什么 | 不知道什么 |
|---|---|---|
| `GameState` | 当前剧情节点、flag | 任何节点引用、任何场景 |
| `WorldLinks` | 场景登记表、出口 → 目的地路由表 | 门长什么样、玩家在哪 |
| `SceneRouter` | 查路由、转场生命周期、到达上下文 | 具体剧情条件、提示文案 |
| `PortalHost` | 本场景的触发盒 / 交互点、冷却、拦截提示 | 出口通向哪个场景 |
| `LetterTransition` | 字母加载屏、切场景本身 | 路由规则 |

依赖方向是单向的：

```
GameState（纯数据）
   ↑
WorldLinks（纯数据 + static resolve）
   ↑
SceneRouter（autoload：状态机 + 转场）
   ↑
PortalHost（场景内节点）
```

`PortalHost` 只调 `SceneRouter.use_portal()`；`SceneRouter` 只调 `WorldLinks.resolve()` 和
`GameState` 的公开方法。**没有任何一层反向查找场景节点。**

## 2. 一次穿越的完整时序

以「商店街西口 → 加油站」为例：

1. `hoshi_street._ready()` 第一件事：
   ```gdscript
   SceneRouter.bind_scene(SCENE_ID)          # 登记当前场景
   _arrival = SceneRouter.consume_arrival()  # 取走「我是怎么来的」，取一次即清空
   ```
2. `_setup_portals()` 创建 `PortalHost`，把本地 `PORTALS` 里的 walk 触发盒和 E 交互点注册进去。
3. 玩家走进 `west_gate` 的触发矩形（或按 E），`PortalHost` 调
   `SceneRouter.use_portal(&"hoshi_street", &"west_gate")`。
4. `SceneRouter` 先用 `WorldLinks.resolve(scene_id, portal_id, GameState.story_node())`
   判断「能不能走、走去哪、落点是谁、转场文案是什么」。
5. 禁用时发出 `portal_blocked(scene_id, portal_id, text)`；`PortalHost` 决定要不要弹 toast
   （默认不弹，见 §8）。
6. 允许时进入 `goto()`：校验目标场景、校验 `set_story_node` 合法性、写入到达上下文、
   把 `_phase` 置为 `LEAVING`、用 `AudioBus.cut_for_transition()` 切掉旧场景的声音，
   并调用旧场景的 `lock_for_transition()`（如果有）。
7. `LetterTransition` 挂在 `get_tree().root` 下播放；`change_scene_to_file()` 之后旧场景销毁，
   新场景的 `_ready()` 在转场动画期间跑完。
8. 新场景在 `_ready()` 里再次 `consume_arrival()`。它拿到的是：
   ```gdscript
   {
       "from_scene": &"hoshi_street",
       "to_scene": &"gas_station",
       "spawn": &"east_sidewalk",
       "via_portal": &"west_gate",
       "mode": &"route",              # route / opening / story
       "meta": {},
       "story_node": &"ep2_station",
   }
   ```
9. `LetterTransition` 等两帧确认新场景已取走上下文，再清空兜底并发出
   `arrival_finished(scene_id, spawn)`。

**到达上下文必须在新场景 `_ready()` 的最前面取走。** 玩家落点、朝向、镜头 yaw、
「是不是死过来的」都靠它决定；晚取一步就可能被别的逻辑先清掉。

## 3. 数据：`SCENES` 与 `ROUTES`

全部在 `scripts/core/world_links.gd`，都是 `const`，没有运行时状态。

### 3.1 场景登记

```gdscript
const SCENES := {
    &"store_walk": {"path": "res://scenes/store_walk.tscn"},
    &"hoshi_street": {"path": "res://scenes/hoshi_street.tscn"},
    &"gas_station": {"path": "res://scenes/gas_station.tscn"},
    &"grassland": {"path": "res://scenes/grassland.tscn"},
    &"opening_flow": {"path": "res://scenes/opening_flow.tscn"},
}
```

只登记 `SceneRouter` 需要按 id 找到的场景。`main` / `diorama_orbit` 不参与路由，不登记。
`store_walk` 已登记但**还没有接路由**（见 §6）。

### 3.2 出口路由

```gdscript
const ROUTES := {
    &"hoshi_street": {
        &"west_gate": {
            "default": {
                "scene": &"gas_station",
                "spawn": &"east_sidewalk",
                "set_story_node": &"ep2_station",
                "transition": {
                    "title": "HOSHIMI",
                    "subtitle": "SERVICE STATION",
                    "footer": "ROUTE 17 · 00:06",
                },
            },
            "routes": {
                &"ep2_dusk": {"enabled": false, "text": "国道方向只剩雨声。现在不是离开商店街的时候。"},
                &"ep3_grassland": {"enabled": false, "text": "旧世界线已经收束。"},
            },
        },
    },
}
```

查找顺序：

1. 精确剧情节点（`routes[story_node]`）
2. 通配 `routes[&"*"]`
3. `default`

命中覆盖项后与 `default` 做**浅合并**，所以「只禁用、不改目标」只写
`{"enabled": false, "text": "..."}` 就够。没有 `default` 且没有命中覆盖项时拒绝。

### 3.3 一个出口的完整字段

| 字段 | 含义 | 默认 |
|---|---|---|
| `scene` | 目标场景 id，必须在 `SCENES` 里 | 无，缺失即拒绝 |
| `spawn` | 目标场景的落点名 | `&"default"` |
| `enabled` | 是否允许通行 | `true` |
| `text` | 禁用时给玩家的理由 | 「现在还不能往那边走」 |
| `set_story_node` | 通行成功后推进到的剧情节点 | 不推进 |
| `transition` | 字母屏文案 `title/subtitle/footer/accent/style` | `LetterTransition` 默认值 |

`resolve()` 是**纯函数**，不读 `GameState` 内部，也不依赖场景树。`router_probe` 正是靠这一点，
用合成表验证「同一出口换剧情节点就换目的地」和 `*` 通配，而不必真的切场景。

## 4. 场景侧接入

每个走路由的场景都要做五件事。以商店街为例：

```gdscript
const SCENE_ID := &"hoshi_street"

# 落点名 → 位置 / 朝向 / 镜头 yaw
const SPAWNS := {
    &"default": {"pos": SPAWN, "face": -PI * 0.5, "cam_yaw": 90.0},
    &"west_gate": {"pos": ARRIVE_FROM_GAS, "face": PI * 0.5, "cam_yaw": 270.0},
}

# 本地出口：只描述触发方式，不写目的地
const PORTALS := [
    {"id": &"west_gate", "triggers": [
        {"kind": "walk",
            "rect": Rect2(WEST_EXIT_X - 1.2, Town.Z0, 1.2, Town.Z1 - Town.Z0)},
    ]},
]

func _ready() -> void:
    SceneRouter.bind_scene(SCENE_ID)
    _arrival = SceneRouter.consume_arrival()
    ...

func _setup_portals() -> void:
    portals = PortalHost.new()
    portals.name = "PortalHost"
    add_child(portals)
    portals.bind(SCENE_ID, PORTALS, player, hud, hub)

func lock_for_transition() -> void:
    player.input_locked = true
    portals.enabled = false
    hub.enabled = false
    hud.hide_prompt()
    hud.hide_toast()
```

### 4.1 触发方式

| `kind` | 字段 | 行为 |
|---|---|---|
| `walk` | `rect: Rect2(x, z, 宽, 深)` | `_process` 里按 xz 平面检测；500ms 内最多重试一次 |
| `interact` | `pos` / `radius` / `prompt` / `priority` | 注册进 `interaction_hub`，按 E 触发 |

同一个出口可以同时挂两种触发（加油站 `east_exit` 就是「走到东缘」或「按 E 问路牌」）。
禁用一次，两种触发同时失效。

`PortalHost` 的 `_interact_gate()` 只决定「这个交互点要不要出提示」：路由允许或
`show_blocked=true` 时才亮。**提示点不应该出现按了没反应的情况。**

### 4.2 `lock_for_transition()` 是可选的，但强烈建议实现

`SceneRouter.goto()` 找到当前场景有这个公开方法时会调用它。它负责把输入、交互、出口、
HUD 提示一起收起来，避免转场期间玩家还能走、还能按 E。
`LetterTransition.play()` 自己也会再调一次（幂等）。

### 4.3 落点解析

```gdscript
func _is_arrival() -> bool:
    return _arrival.get("to_scene", &"") == SCENE_ID

func _spawn_data() -> Dictionary:
    var key: StringName = &"default"
    if _is_arrival():
        key = _arrival.get("spawn", &"default")
    return SPAWNS.get(key, SPAWNS[&"default"])
```

- `_is_arrival()` 必须同时检查 `to_scene`：场景可能被直接实例化（probe、编辑器），
  这时上下文为空，应走开场运镜而不是「到达」分支。
- `SPAWNS` 里的 `face` / `cam_yaw` 要和旧落点分支一致，否则玩家一回来镜头就对着脸。
- 到达上下文不匹配时，场景会 `push_warning` 并清空，不要硬用。

## 5. 剧情节点

`GameState.KNOWN_NODES` 是唯一白名单：

| 节点 | 含义 |
|---|---|
| `ep1_store` | 雨夜便利店（默认） |
| `ep2_station` | 加油站 · 逢魔前 |
| `ep2_dusk` | 加油站 · 逢魔时 |
| `ep3_grassland` | 异世界草原 |

规则：

- `set_story_node()` 只接受白名单里的 id，拼错当场失败，不会静默落进「没有路由覆盖」。
- **反向出口不写 `set_story_node`。** 加油站 `east_exit` 回商店街时不推进节点，
  否则从加油站回来会把剧情倒回第二幕。
- 剧情强制转场（死亡去草原）直接调 `SceneRouter.goto(..., {"mode": "story"})`，
  不走出口路由，但仍归 `SceneRouter` 管目的地与到达方式。
- 草原用 `from_scene == gas_station && mode == story` 判断要不要播苏醒独白，
  不再用 root 上的全局 meta。meta 谁都能写、也谁都会忘删。

## 6. 当前路网

| 出口 | 触发 | 默认去向 | 剧情限制 |
|---|---|---|---|
| `hoshi_street.west_gate` | walk（西端 1.2m 竖条） | `gas_station.east_sidewalk`，并推进到 `ep2_station` | `ep2_dusk` / `ep3_grassland` 禁用并给理由 |
| `gas_station.east_exit` | walk（东缘）或 E（路牌） | `hoshi_street.west_gate` | `ep2_dusk` / `ep3_grassland` 禁用并给理由 |
| 剧情强制转场 | `gas_station_story._finish()` | `grassland`，`mode=story`，推进到 `ep3_grassland` | 固定 |
| 开场流程 | `opening_flow._go_next()` | `grassland`，`mode=opening`，推进到 `ep3_grassland` | 固定 |

```
opening_flow ──goto(ep3)──────────────→ grassland
gas_station_story ──goto(ep3, story)──→ grassland
hoshi_street.west_gate ──walk─────────→ gas_station.east_sidewalk
gas_station.east_exit ──walk / E──────→ hoshi_street.west_gate
store_walk（默认入口，尚未接路由）
grassland（有 Scene_ID，无出口）
main / diorama_orbit（展示版，不经路由）
```

`store_walk` 目前只 `bind_scene` 之外的逻辑都没接：它没有 `SCENE_ID`、没有 `PORTALS`、
也没有 `consume_arrival()`。它仍是 `project.godot` 的默认入口，所以**不能删**；
以后要给它加出口时，按第 7 节的完整清单做，不要只补一半。

## 7. 新增场景 / 新增出口

### 7.1 新增一个可被路由的场景

1. 在 `WorldLinks.SCENES` 登记 `scene_id → path`。
2. 场景脚本顶部加 `const SCENE_ID`，`_ready()` 第一行 `bind_scene()` + `consume_arrival()`。
3. 加 `SPAWNS` 表（至少 `default`），落点和开场分支保持一致。
4. 需要出口时加 `PORTALS` + `PortalHost`；不需要出口也可以只登记（草原就是）。
5. 在 `WorldLinks.ROUTES` 里为每个本地出口写 `default`（可以暂时 `enabled: false`）。
6. 扩 `router_probe._check_local_portals()`：preload 新场景，断言 `SCENE_ID` 与
   `PORTALS` 的 id 集合和中央 `ROUTES` 双向一致。

### 7.2 新增一个出口

1. 场景 `PORTALS` 加一项：`id` + 一种或两种触发。
2. `WorldLinks.ROUTES[scene_id][portal_id]` 写 `default`（目标场景、spawn、可选转场文案）。
3. 需要按章节禁用 / 改指向时，在 `routes` 下加覆盖项；只禁用就写 `enabled:false + text`。
4. 如果目标场景没有对应的 `spawn` 名，在它的 `SPAWNS` 里补一个，不要复用 `default` 蒙混。
5. 跑 `./tools/run.sh --headless router_probe`，它会把「本地有出口但中央没路由」和
   「中央有路由但本地没出口」都报出来。

## 8. 常见坑

- **到达上下文只取一次。** `consume_arrival()` 之后 `has_arrival()` 就是 false。
  不要在 `_process` 里反复读；需要延后使用的值（如草原的苏醒独白）在 `_ready()` 存一份。
- **转场层同一时间只能有一个。** `goto()` 发现 `root` 下已有 `LetterTransition` 会拒绝第二次切换。
  这是为了防「旧场景自己起转场 + 路由又起一层」把输入锁死。
- **`set_story_node` 失败会中止整个切换。** 校验放在改状态之前，失败的 `goto` 不应留下任何状态变更。
- **禁用出口默认连提示都不出现。** 只有确实需要告诉玩家「为什么不行」时才设
  `show_blocked=true`；否则玩家会看到一个按了没反应的点。
- **walk 触发不是每帧切场景。** 同一出口 500ms 内最多重试一次；切场景后 `PortalHost.arm()`
  给一小段冷却，防止落在触发盒里立刻又被送走。
- **`stage_arrival()` 只写上下文、不切场景。** 它给 probe 和调试传送用；不要拿它做正式入口。
- **`from_scene` 来自 `bind_scene()`。** 场景忘了 bind 就切走，到达上下文里的来源会是空。
- **不要直接 `change_scene_to_file()`。** 那样会绕过到达上下文、转场文案和剧情推进；
  唯一例外是 `LetterTransition` 自己执行的那一次。

## 9. 验证

| probe | 覆盖 |
|---|---|
| `router_probe` | 80 条：默认路由、剧情覆盖、禁用理由、同一出口改指向、`*` 通配、`set_story_node` 合法性、本地 `PORTALS` 与中央 `ROUTES` 双向一致、`GameState` 与 `SceneRouter` 到达上下文 |
| `gas_station_probe` | 到达上下文清空、锁定后玩家 / 中枢 / 出口同时停用、柜台隔窗提示 |
| `transition_probe` | 字母屏层级、字母拆分、进度、自毁（不真的换场景） |
| `street_probe` | 从商店街走到便利店，验证出口没有把街区走通成「穿墙」 |

```bash
./tools/run.sh --headless router_probe
./tools/run.sh --headless transition_probe
./tools/check.sh
```

`router_probe` 是纯数据测试：不建 3D 节点、不切场景，因为转场一旦真的跑起来会把探针自己换掉。
需要验证「到了新场景之后」的行为，交给目标场景自己的 probe。
