## 0. 先读这一节：本工程的写法约定

**这个工程没有一个编辑器摆出来的场景。** 整个仓库只有：

```
scenes/main.tscn        6 行，一个空 Node3D + 挂一个脚本
scripts/main.gd         所有东西都在 _ready() 里用代码生成
scripts/kit.gd          建模工具库（体块/圆柱/材质缓存），造东西全用它
scripts/actor.gd        角色（已实现，见第 2 节）
shaders/                自定义着色器（toon / outline / …）
assets/characters/      gaia.glb（主角模型）
```

**新场景必须遵守同样的写法**：`.tscn` 只放一个根节点 + 一个脚本，几何体全部由 GDScript 生成。
**不要在编辑器里拖节点，不要手写大段 Transform3D。**

### 2.2 复用 `scripts/actor.gd`，不要重写

它已经做好：加载 glb、`_apply_pose(pose_name)`（`stand` / `cover_head`）、
T-pose 掰手臂的已验证参数、按 surface 重建材质、挂描边。

**已验过的掰手臂参数（照抄）：**

```gdscript
var z := Vector3(0.0, 0.0, 1.0)
skel.set_bone_pose_rotation(skel.find_bone("J_Bip_L_UpperArm"), Quaternion(z, -1.22))
skel.set_bone_pose_rotation(skel.find_bone("J_Bip_R_UpperArm"), Quaternion(z,  1.22))
skel.set_bone_pose_rotation(skel.find_bone("J_Bip_L_LowerArm"), Quaternion(z, -0.12))
skel.set_bone_pose_rotation(skel.find_bone("J_Bip_R_LowerArm"), Quaternion(z,  0.12))
```

- 绕 **Z 轴**，负角度对左臂、正角度对右臂。
- **前臂只能绕 Z 轴弯**，绕 X 轴是沿骨骼自身扭转，手不会动（已验证）。
- 期望结果：双手落到胯部高度、左右对称。

## 3. 醒来（本场景的开场）

没有动画资源，用补间做，效果够用：

1. 角色初始**躺在地上**：模型绕 X 轴 −80°，`position.y` 略低于 0（让身体贴地）
2. 相机同时从低处（`y ≈ 0.4`）起
3. 2 秒内：
   - 模型 `rotation.x` → 0（`TRANS_SINE` / `EASE_OUT`）
   - 模型 `position.y` → 0
   - 相机高度 → 正常跟随高度
4. 结束后 `player_controller` 才接受输入

要点：**补间作用在模型子节点上**，不要动 `CharacterBody3D` 自己的 transform（会和物理打架）。
期间把控制器的输入锁住（`input_locked = true`），醒来后解锁。

## 5. 玩家控制器：移植，不要重写

`F:\demo1\dev\scripts\player.gd` 里有一个**已实测可用**的第三人称控制器：
CharacterBody3D + SpringArm3D 相机（贴墙回缩）、coyote time、jump buffer、可变跳跃高度、自动上台阶。

**移植到 `scripts/player_controller.gd`，并删掉这些依赖：**

| 要删的 | 原因 |
|---|---|
| `Dialogue.is_active()` 的判定 | 本工程没有 `Dialogue` autoload |
| 上台阶相关（`toggle_step_up` 等） | 草原是平的，先不需要 |
| `Input.is_action_pressed("restart")` 等 | 本任务不需要重开 |

### 5.1 输入用代码注册，**不要改 `project.godot`**

```gdscript
func _ensure_actions() -> void:
	for spec in [
		{"name": "move_forward",  "keys": [KEY_W, KEY_UP]},
		{"name": "move_backward", "keys": [KEY_S, KEY_DOWN]},
		{"name": "move_left",     "keys": [KEY_A, KEY_LEFT]},
		{"name": "move_right",    "keys": [KEY_D, KEY_RIGHT]},
		{"name": "jump",          "keys": [KEY_SPACE]},
		{"name": "sprint",        "keys": [KEY_SHIFT]},
	]:
		if InputMap.has_action(spec["name"]):
			continue
		InputMap.add_action(spec["name"])
		for k in spec["keys"]:
			var ev := InputEventKey.new()
			ev.physical_keycode = k
			InputMap.action_add_event(spec["name"], ev)
```

在 `_ready()` 里调用一次。

### 5.2 朝向必须对齐

模型**脸朝 +Z**。控制器里 `visual.rotation.y = atan2(dir.x, dir.z)` 的含义是
"让 +Z 指向移动方向"——**正好匹配，不要再加 180°**。

如果画面里角色倒着走，说明你加了多余的旋转，去掉。

## 6. 地形与光照（二次元中世纪基调）

**目标：明亮、饱和、干净。要和练手那个雨夜场景形成强烈反差**（这是"穿越"的视觉信号）。

| 元素 | 参数 |
|---|---|
| 地面 | `PlaneMesh` **400 × 400**（够大，别用细分，`subdivide` 保持 0 或少） |
| 地面材质 | 绿色，`#6f9a4e` 附近，`roughness = 1.0`，不要金属感 |
| 色差 | 用 `NoiseTexture2D` 做 albedo，尺度大一点，避免"一整块塑料绿" |
| 天空 | `ProceduralSkyMaterial`：天蓝 `#7fb8e8` → 地平线偏白，`sky_curve` 低一点 |
| 太阳 | 一盏 `DirectionalLight3D`，偏暖白，`light_energy ≈ 1.2`，**开阴影**，角度高（上午） |
| 雾 | 淡雾，`fog_density ≈ 0.004`，主要是**掩盖 400 m 平面的边缘** |
| 远景（可选） | 3–5 块很大的低多边形缓丘轮廓放在远处，收住地平线，避免"无穷大平板"的空洞感 |

**不要做**：草叶粒子、树木、石头、建筑、路、云、后处理特效。

> "好渲染"是硬要求：这个场景要能在低配机器上满帧跑，也不要让后续加内容时被性能拖住。
